# ADR-0001: 静的SPAをGitHub Pagesに置き、データは端末のIndexedDBに保存する

- ステータス: 承認済み
- 日付: 2026-10-31
- 決定者: ryu

## コンテキスト

GitHub Pagesは静的ファイルしか配信できず、サーバー側の処理やデータベースを持てない。読書記録は個人のデータで、サーバー費用・アカウント管理・秘密情報の管理は避けたい。リポジトリはpublicにする。

## 決定

アプリをすべてブラウザで動く静的SPAとし、記録はIndexedDBに保存する。バックアップと端末間の移行は、JSONのエクスポート・インポートで行う。`navigator.storage.persist()` を要求し、最終エクスポートからの経過日数を表示して、エクスポートを促す。

## 検討した選択肢

### A) IndexedDB＋JSON入出力（採用）

- 良い点: 認証・費用・秘密情報が要らない。オフラインで動く。データが端末の外へ出ない。
- 悪い点: 端末間で自動では同期しない。ブラウザのデータ消去で消えうる。

### B) GitHubリポジトリ／GistにPATでJSONを保存

- 良い点: 端末間で同期でき、履歴も残る。
- 悪い点: 各端末でトークンを管理する必要がある。トークンがXSSで漏れると被害が大きい。

### C) FirebaseなどのBaaS

- 良い点: ログインとリアルタイム同期が楽。
- 悪い点: 外部サービスの設定・無料枠の管理が増える。

## 結果

- 同期が必要になったら、B（Gist）をオプション機能として追加するかを、別のADRで判断する。
- エクスポートの形式（`schemaVersion`）を最初から固定し、移行関数で互換性を保つ。

## 追記（2026-11-01、おすすめ）

ユーザーの依頼で「おすすめ」タブを追加した。そのため、記録から導いた一部の情報を外部に送る。

- 送るもの: よく読む著者名（最大3人）、読んだシリーズ名（最大5件）、ジャンルID。送り先は楽天ブックス書籍検索APIだけ。
- 送らないもの: 読書記録そのもの（状態・日付・評価・メモ・タグ・進捗）。
- 楽天のアプリIDを設定した利用者が「おすすめ」タブを開いたときだけ送る。そのことを画面に明記している。
- 楽天の制限（1アプリIDにつき1秒1回）に合わせ、問い合わせは1.1秒間隔で順に送り、同じ問い合わせの結果は開いている間だけ使い回す（`src/lookup/recommend.ts`）。
