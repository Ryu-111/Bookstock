# ADR-0003: 書誌はキー不要のAPIを openBD → NDLサーチ → Google Books の順に引く

- ステータス: 承認済み
- 日付: 2026-10-31
- 決定者: ryu

## コンテキスト

静的サイトにAPIキーを置くと、公開されてしまう。国内の紙の本はopenBDの収録が厚い。電子書籍・オーディオブックや洋書は、ISBNがないか、openBDにないことが多い。

## 決定

- ISBN検索: openBD → 国立国会図書館サーチ（OpenSearch）→ Google Books の順に引き、最初に見つかった結果を使う。足りない項目（書影、ページ数）は、後のAPIの結果で補う。
- タイトル検索: NDLサーチとGoogle Books。
- 各リクエストは5秒で打ち切る。すべて失敗したら手入力フォームを出す。
- 応答は境界で検証し、`Book` に変換する。テストは合成fixtureを使い、実APIを呼ばない。
- 楽天ブックスAPIなど、キーを要するAPIは使わない。

## 結果

- NDLサーチがブラウザから直接呼べるか（CORS）は、M1のspikeで確認する。呼べなければ、NDLは外す。
- Google Booksはキーなしだと日次の上限がある。超えたら手入力に回す。

## 追記（2026-10-31、M1）

決定は変えない。実装で分かったことを残す。

- openBD v1は、2023年に提供終了が発表されている。代替APIは収録範囲を変えて提供する方針（[カレントアウェアネス](https://current.ndl.go.jp/car/185804)）。現在の状態は未確認。openBDが失敗・空でもNDLに進むので、止まっても登録は続けられる。
- Google Booksは `Access-Control-Allow-Origin` を返し、ブラウザから呼べる。ただし、キーなしの呼び出しは共有の日次クォータで429になることがある（開発環境で確認）。429は「上限」として表示する。
- NDLサーチのCORSと、openBDの応答は、開発環境のネットワークでは遮断されて確かめられなかった。トップページの検索フォームで、APIごとの成否（成功 / 該当なし / タイムアウト / 通信失敗 / HTTPエラー / 上限）をブラウザで確かめる。
- ISBN検索は、書影とページ数がそろった時点で、残りのAPIを呼ばない。

## 追記（2026-11-01、楽天ブックスAPI）

ユーザーと合意して、キーなしの原則を次のように補う。リポジトリと公開ページには、引き続きキーを置かない。

- ユーザーが設定画面に、自分の楽天ウェブサービスのアプリID（必要ならアクセスキー）を入れた場合だけ、楽天ブックス書籍検索APIを使う。
  - ISBN検索では最初に引き、タイトル検索ではNDL・Googleと並行に引く。
  - 書影・出版日・読み仮名（`titleKana`）を取る。ページ数とNDCはNDLなどで補う。
- 値はそのブラウザの `localStorage` にだけ保存し、JSONの書き出しには含めない。送り先は `https://〜.rakuten.co.jp` に限る（`src/lookup/rakuten.ts`）。
- 2026年にエンドポイントのドメインと認証（`accessKey`）が変わったという報告があるが、開発環境からは公式ドキュメントに届かず未確認。
  - 既定値は `openapi.rakuten.co.jp/services/api/BooksBook/Search/20170404`（2026-11-01更新）。旧URL（`app.rakuten.co.jp/…`）に新形式のIDを送ると `wrong_parameter: specify valid applicationId` になることを、ユーザーのブラウザで確認した。旧URLを保存した設定は新しいURLに読み替える。新URLは複数の開発者の報告による値で、公式ページは開発環境から未確認。
  - 旧URLへのブラウザからの呼び出しはCORSで拒否されず、APIのエラー文が返った（ユーザーのブラウザで確認）。
  - 設定画面でURLを差し替えられる。接続テストは、APIのエラー文をそのまま表示する。

### 追記（2026-11-01、公式ドキュメントの確認）

ユーザーが別のツールで公式ドキュメント（`webservice.rakuten.co.jp/documentation/books-book-search`、公式ブログの移行告知、ヘルプ）を確認した結果に合わせた。

- エンドポイントは `https://openapi.rakuten.co.jp/services/api/BooksBook/Search/20170404` で確定。旧ドメインは2026-05-14に廃止された。
- `applicationId`（クエリ）と `accessKey`（ヘッダーかクエリ）は必須。プリフライトを避けるため、`accessKey` もクエリで送る。
- アプリ登録で「許可するWebサイト」が必須。Referer / Origin の照合方法とCORSの条件は公式文書に記載がない。旧URLへのブラウザからの呼び出しでは、APIのエラー文が返った（CORSで拒否されなかった）。
- JSON（`formatVersion=2`）の配列は小文字の `items`。`Items` / `Item` も受け付ける。
- `outOfStockFlag` の既定値（0）は品切れ・販売終了の本を除くため、`1` を送る。
- 該当なしは404 `not_found` で返るので「該当なし」として扱う。IDやキーの誤りは400 `wrong_parameter`（説明に applicationId / accessKey を含む）として「IDの設定エラー」と表示する。
- 制限は1アプリIDにつき1秒1回。超えると429。
- ページ数は応答に含まれないため、NDLなどで補う（既存の仕組み）。

### 追記（2026-11-01、実機での接続）

- 「許可するWebサイト」が未登録のときは、新しい形式のIDとアクセスキーでも接続テストが失敗した。エラーはドキュメントの `{error, error_description}` の形ではなかった（401か403と推定）。登録すると接続できた（ユーザーのブラウザで確認）。
- これを受けて、楽天の失敗には `HTTP 403` などのステータスと、本文から取り出した説明（想定外の形なら本文の先頭）を表示する。送ったアプリID・アクセスキーは伏せ字にする。`auth` は「IDまたは許可サイトの設定エラー」と表示する。
- 著者での検索を追加した。楽天は `author`、NDLサーチは `creator`、Google Booksは `inauthor:` を使う。

### 追記（2026-11-02、オーディオブックの長さ）

- Audibleには公開APIがない。非公式のカタログAPIはあるが、利用規約上の位置づけとブラウザからの呼び出し（CORS）が不明なので、使わない。
- 代わりに、記録の画面に「Audibleで探す」（`https://www.audible.co.jp/search?keywords=<題名 著者>`）を置き、ユーザーが押したときだけ題名と著者を渡す。
- 長さが分からない本は、ページ数から推定する（1ページ≒1.7分）。統計では「推定」と明示する。
